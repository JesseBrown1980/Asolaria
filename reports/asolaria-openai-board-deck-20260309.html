Governance

The system treats tool use as governed infrastructure, not invisible model side effects.

Mode 01

Authority is explicit

`operator_primary`, `shared_control`, and `asolaria_primary` are first-class modes with request, confirm, and rollback flows.

Mode 02

Approvals are bindable

Approval records are one-time, tied to tool id plus input hash, and expire by TTL.

Mode 03

Audit can lock writes

If audit verification fails, control-write actions can be blocked until integrity is restored.

Why this matters

If frontier models are going to run real tools, this is the pattern: explicit authority, approval gates, readiness drills, and verifiable audit.

Sources: `docs/GATEWAY_TOOL_AUTHORITY.md`, `docs/AUTHORITY_MODES.md`.

Cloud and Context

GCP, Vertex, NotebookLM, and Augment are integrated with restraint.

GCP and Vertex

  • Service-account backed
  • Allowed-project enforcement
  • Read-only default cloud scope posture
  • Allowlisted admin service enabling
  • Daily request and token budgets for Vertex

Augment / Auggie

  • Read-only context sidecar, not a second brain
  • `local_cli` for same-machine retrieval
  • `remote_mcp` for narrow cross-runtime bridge
  • Allowed tools limited to `codebase-retrieval`

The design choice is the point: external systems strengthen local reasoning without bypassing governance.

Graph Layer

The graph runtime is live now, and the GNN posture is unusually mature because it is honest.

What is live

  • Typed graph events
  • Typed action manifests
  • Edge-risk scoring at event-build time
  • Training dataset export over graph-runtime windows

What is not claimed

  • No evidence of GNN inference in the hot path
  • Policy and approvals remain the root of trust
  • Graph learning is positioned as a sidecar for ranking and anomaly support

The state-of-the-art move is not "we shoved a GNN into the critical path." The state-of-the-art move is to instrument the control plane first.

Multi-Machine Fabric

The system scales outward through relay, watchdog, and bootstrap patterns.

Relay colony

  • Room-based message relay with bearer auth
  • Allowlists and per-sender token enforcement
  • Cloudflare tunnel support
  • Watchdog restart behavior and identity checks

Cross-host bootstrap

  • Host discovery before install
  • Machine-specific toolchain inventory
  • Path and runtime adaptation per OS
  • Repeatable path for another workstation or Mac build-out

The key proof is not one giant script. It is the operational doctrine for cloning the control-plane logic onto another host without losing identity, governance, or recovery behavior.

Sources: `bridge.js`, `AIRLOCK_BOTS.md`, `ASOLARIA_COLONY_STARTUP.md`, and friend-bootstrap task materials.
