Appendix A - Ticket #1072 key notes
Current behavior observed
In some cases, our logs show a CareTendDocumentId, but the PDF is not visible under the intended patient in CareTend.
Endpoint behavior differed between documents/externalfile and documents/patient, creating ambiguity during testing.
Fixes implemented
Standardized document creation uploads to POST documents/patient (patient-visible document endpoint).
Corrected JSON serialization for nested assignedTo fields to ensure camelCase property names match CareTend expectations.
Added full request/response logging (including raw response body) for diagnostics.
Added a verification endpoint to confirm document retrievability by CareTendDocumentId.
Validation checklist
Trigger one nursing note upload (manual or background job).
Confirm response status and DocumentId returned.
Call verification endpoint using the DocumentId.
Confirm document appears under the correct patient in CareTend UI.
Confirm tracking row updated (Status=Success, CareTendDocumentId populated, UploadedAt populated).
Appendix B - Support notes and Q&A
If asked: what was the likely root cause?
The most likely root cause was a request payload mapping/serialization mismatch in nested fields. CareTend appears to be sensitive to the expected JSON property names in assignedTo. When nested properties were serialized in PascalCase instead of camelCase, CareTend could return an ID but fail to reliably link the document to the patient.
