BUGS FOUND AND FIXED:

  Bug A — Yup schema has no defaults for limit/offset/sort
    File: apps/web-ebacmap/src/pages/api/test-definitions/index.ts
    Problem: limit, offset, and sort are yup.number().notRequired() / yup.string().notRequired()
             with NO .default() value. When query params are omitted, these pass through
             as undefined. While the repo has || fallbacks, having defaults in the schema
             is the proper defensive layer — prevents undefined from reaching the use case
             and avoids any edge-case coercion issues (e.g. empty string -> NaN).
    Fix: Added .default(10), .default(0), .default('_id:-1') to yup schema.

  Bug B — organismId not validated before new ObjectId()
    File: apps/web-ebacmap/src/modules/test-results/repos/TestDefinitionRepo.ts
    Problem: In search(), categoryId goes through MongoIdentifier.build() validation
             before being used in new ObjectId(), but organismId does NOT.
             If an invalid ObjectId string is passed as organismId (anything other than
             a 24-char hex string), `new ObjectId(invalidString)` throws a BSONError,
             which bubbles up as a 500 Internal Server Error.
    Fix: Added the same MongoIdentifier.build() validation pattern for organismId
         that already existed for categoryId. Invalid organismId values are now
         silently excluded from the match filter instead of crashing.
