3. LOCKFILE (pnpm-lock.yaml)
-----------------------------

  This is the pnpm 9.x lockfile format. pnpm 10 uses lockfileVersion
  '10.0'. The two formats are NOT cross-compatible:
  - pnpm 10 reading a v9 lockfile will silently regenerate it as v10
  - pnpm 9 reading a v10 lockfile will fail or regenerate it as v9

  This is the ONLY real friction point, and it's a one-time migration.

5. DO WE NEED TWO BRANCHES?
----------------------------
  NO. Here is why:

  a) The only difference between the branches is the pnpm version
     pin and the lockfile format. There are no code changes between
     them — same source, same tests, same dependencies.

  b) Corepack solves the version problem at the tool level. Once
     packageManager is set, every developer gets the right pnpm
     version automatically. No branch needed.

  c) Maintaining two branches means double the merge work for every
     feature PR. The lockfile will conflict on every merge. This is
     pure overhead with zero benefit.

  d) The lockfile format change is a ONE-TIME migration. You do it
     once (Branch A), and it's done forever.
