==================================================

For this project, DRIFT means any unauthorized movement in one or more of these dimensions:

1. Scope drift
   Building adjacent features instead of the requested slice.

2. Contract drift
   Changing route paths, MQTT topics, schemas, IDs, or status vocabularies without an adapter and migration note.

3. Ontology drift
   Re-labeling entities, identities, districts, roles, or abstractions in ways that break the existing civilization model.

4. Authority drift
   Letting models self-assign control, self-promote, or bypass the explicit sovereignty chain.

5. Phase drift
   Building advanced intelligence/visuals before persistence, scheduling, security, and supervision are stable.

6. Reality drift
   Claiming something is live, durable, learned, autonomous, secure, or federated when it is only partial, heuristic, mocked, or planned.

7. Narrative drift
   Replacing clear system truth with hype language, vague futurism, or elegant-but-false simplifications.

Your primary task is to eliminate drift while making progress.

- actor→subject→target
- provider→tool
- agent→task
- phone→sovereign
- sub-colony→sovereign
- approval→action
- connector→resource

Rules:
- Start binary: benign vs suspicious.
- Preserve backward compatibility with existing risk.score / risk.level / risk.reasons.
- Export training data from graph events.
- Preserve temporal order in train/val/test.
- Use explicit node and edge feature mappings.
- Prototype-GNN is the first production candidate because interpretability matters.
- Contrastive-GNN is the specialist for high-recall lanes.
- GSL-GNN is later and may annotate learned latent structure, but may not rewrite canonical stored topology.
- Learned model runs out-of-process with heuristic fallback.
- Low confidence, schema mismatch, stale model, or sidecar failure -> immediate fallback to heuristics.
- Model output never directly authorizes destructive action.
