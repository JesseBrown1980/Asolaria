1. SYNC-SERVER (apps/sync-server)
================================================================================

VERSION: 2.0.1 (package.json) / 1.1.1 (src/version.ts) -- MISMATCH
PORT: env SERIAL_PORT, default 7700
ENTRY: src/index.ts -> Socket -> SyncClient
BUILD: esbuild via build.mjs, outputs dist/index.js (ESM)
RUNTIME: Node 20.14 (Dockerfile), pnpm 9.12.2
DOCKER EXPOSE: 443

PURPOSE:
  TCP socket server that syncs NovaLUM hardware devices to eBacMap MongoDB.
  Bidirectional: reads device data (globals, firmware, channels, surfaces,
  locations, plans, assays, notes, operators), writes updates back.

ARCHITECTURE:
  index.ts       - Connects MongoDB, creates Socket instance
  socket.ts      - net.createServer, spawns SyncClient per connection
  SyncClient.ts  - Main state machine (~1870 lines). Read/write protocol.
  mapper.ts      - processSerialData: maps assays -> test results, queues jobs
  dbMapper.ts    - Maps serial protocol objects to/from MongoDB documents
  dbToSerialMapper.ts - Converts DB docs to serial protocol format
  writer.ts      - Reads DB for sync: surfaces, sites, channels, plans, notes, operators
  models/        - 10 serial protocol models (Assay, Channel, Firmware, Globals,
                   Location, Plan, PlanEntry, SerialModel, Surface, CannedNote, CannedOperator)
  utils/         - encryption.ts, logger.ts, messages.ts, parse.ts, twofish.js

ENCRYPTION:
  Twofish-256-CBC via bcrypto library.
  Key hardcoded: "CHARMSCICHARMSCICHARMSCICHARMSCI" (32 bytes)
  IV hardcoded: 00100200300400500600700800901002
  Toggled by env USE_ENCRYPTION=true
  NOTE: Key and IV are in source code (encryption.ts lines 2-3). Security concern
  if repo is public. twofish.js is a standalone JS implementation (unused, bcrypto used instead).

WORKSPACE DEPS: @ebacmap/common, @ebacmap/db, @ebacmap/domains, @ebacmap/types, @ebacmap/utils
  All resolved from libs/ directory (workspace:*)
  Specific imports used:
    - @ebacmap/db: getConnection, MongooseModels, document types
    - @ebacmap/common: MongoIdentifier, NotFoundError
    - @ebacmap/domains: Unit, Channel, CorrectiveNote, Plan, Site, SurfaceType, TestResult, etc.
    - @ebacmap/types: QUEUE_USECASE
    - @ebacmap/utils: getEnvFromApiUrl, chunkArray, getLastSiteId, getLastChannelId, etc.

SENTRY:
  DSN: https://0b05cfede9714f0c8f8a4c658bf62782@o477196.ingest.sentry.io/6653692
  Environment: 'serial-server'

SYNC FLOW (state machine):
  1. readGlobals -> identify unit by serial number
  2. readFirmware -> check version
  3. IF unit.hasUpdates: readChannels -> readSurfaces -> readLocations -> readPlans
  4. readAssays (always)
  5. readNotes, readOperators
  6. writeChannels -> writeSurfaces -> writeLocations -> writePlans
  7. writeNotes, writeOperators
  8. updateGlobals -> deleteAssays -> endSyncProcess
  Timeout: 90s inactivity disconnects client.

QUEUE INTEGRATION:
  mapper.ts queues jobs to MongoDB QueueModel:
  - SEND_NOTIFICATIONS (after test results created)
  - CHECK_SWABS_FOR_COMPLETED_TESTS

SUBSCRIPTION CHECK:
  mapper.ts checks clientHasSubscription for CAPA_PRODUCT_ID (env var)
  before processing assays. CAPA access gates corrective action features.

EZ PROTECT in sync-server: NONE
  Zero references to ezProtect, ez_protect, or EZ Protect anywhere in sync-server.
  The sync server handles NovaLUM device protocol only -- EZ Protect is a
  web-app-level feature, not part of device sync.

POTENTIAL ISSUES (sync-server):
  1. VERSION MISMATCH: package.json says 2.0.1, src/version.ts says 1.1.1.
     The version.ts value is what gets displayed to devices during sync.
  2. HARDCODED CRYPTO: encryption.ts has key/IV in plaintext source code.
  3. Dockerfile EXPOSE 443 but default port is 7700 -- mismatch.
  4. Error handlers commented out (socket.ts lines 46-48, 73-74).
  5. Several @ts-ignore annotations in dbToSerialMapper.ts.
  6. twofish.js exists but is unused (bcrypto is used instead). Dead code.

BROKEN REFERENCES (sync-server): NONE FOUND
  All local imports (./models/*, ./utils/*, etc.) resolve to existing files.
  All @ebacmap/* workspace imports correspond to existing libs/ packages.

BROKEN REFERENCES (admin): NONE CONFIRMED
  All @ebacmap/* imports point to existing libs/ packages.
  The next.config.js has ignoreBuildErrors: true and ignoreDuringBuilds: true,
  which means TypeScript and ESLint errors are suppressed during build.
  This masks potential type mismatches at build time.

POTENTIAL ISSUES (admin):
  1. BOTH Playwright AND Puppeteer in deps. Likely only one needed. Both are heavy.
  2. Both react-md v5 AND @react-md/core v6 in deps. Migration may be incomplete.
  3. next.config.js suppresses TS and ESLint errors -- masks real issues.
  4. moment.js still used alongside date-fns. Should consolidate.
  5. formik AND react-hook-form both in deps. Two form libraries.
  6. webpack fallback list is very long (30+ node modules) -- sign of server-side
     code leaking into client bundles.
  7. No explicit EZ Protect API routes -- feature is managed through subscription
     features and user permissions only. No dedicated EZ Protect CRUD.

3. CROSS-APP ANALYSIS
================================================================================

SHARED WORKSPACE PACKAGES (libs/):
  @ebacmap/common   - MongoIdentifier, Result, UseCase, errors, email
  @ebacmap/db       - MongoDB connection, models, document types
  @ebacmap/domains  - Domain entities (Unit, User, Client, etc.)
  @ebacmap/types    - Shared TypeScript types, enums
  @ebacmap/utils    - Utility functions (queue, serialModels, Array)

THIRD APP: apps/queue-server also exists (separate scan needed).

CONNECTION BETWEEN SYNC-SERVER AND ADMIN:
  - sync-server writes test results and queues jobs to MongoDB
  - admin reads from same MongoDB to display data
  - No direct API calls between them
  - Queue jobs created by sync-server are processed by queue-server (not admin)
  - Both use the same MongooseModels from @ebacmap/db

EZ PROTECT INTEGRATION SUMMARY:
  - sync-server: NO integration. Device protocol has no EZ Protect concept.
  - admin: YES, fully integrated as a subscription feature and permission system.
  - EZ Protect is a web-app feature for environmental monitoring corrective actions,
    not a device-sync feature. The separation is correct.

MISSING PIECES:
  1. No EZ Protect lot/roll tracking found in either app.
     The PQ Bid scaffold mentioned in recent QDD commits is not present in these apps.
  2. sync-server version.ts (1.1.1) is stale vs package.json (2.0.1).
  3. No test files for admin modules (modules/ directory has no *.test.* files).
     Tests exist in specs/ directory and jest config, but module-level unit tests missing.
  4. sync-server has only 2 test files: encryption.unit.ts and parser.unit.ts.
  5. The CAPA subscription check in mapper.ts uses env CAPA_PRODUCT_ID but there is
     no similar env check for EZ Protect in sync-server (expected, since EZ Protect
     is admin-only).
