SECTION 13: POTENTIAL BUGS IN WRITE FUNCTIONS
================================================================================

The Phase 4 write functions (createContact, createDeal, updateContact) at lines
750-771 may have implementation issues:

  createContact calls:
    hubspotApiRequest({ method: "POST", path: "...", body: JSON.stringify(body),
                        accessToken: token.access_token })

  But hubspotApiRequest() expects:
    { method, url (full URL, not path), body (object, not string),
      portalId/account (not accessToken) }

  Issues:
    1. Uses 'path' but hubspotApiRequest checks 'url' — rawUrl will be empty
    2. Uses 'accessToken' param but hubspotApiRequest uses ensureAccessToken()
    3. body is pre-stringified but hubspotApiRequest will JSON.stringify again
    4. ensureAccessToken() is called with 'account' from input, but these
       functions pass token.access_token as if it were a direct param

  These functions have likely never been tested. The read functions
  (listContacts, listCompanies, listDeals) use the HubSpot API correctly
  via direct fetch calls, not through hubspotApiRequest().
