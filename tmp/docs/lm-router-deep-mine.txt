PURPOSE: The primary "which LLM answers this question" router.
         Called by the /api/providers/brain/run endpoint.

DEFAULT PROVIDER CHAIN (hard-coded fallback order):
  1. anthropic    (Claude CLI)
  2. codex        (OpenAI Codex CLI — local agent)
  3. gemini-api   (Google Gemini API — REST)
  4. vertex       (Google Vertex AI — GCP)
  5. gemini-cli   (Google Gemini CLI)
  6. openclaw     (OpenClaw local agent)
  7. openai       (OpenAI API via externalBrainConnector)
  8. cursor       (Cursor API via externalBrainConnector)
  9. antigravity  (Antigravity API via externalBrainConnector)

EFFECTIVE ORDER (runtime):
  Built by buildEffectiveProviderOrder(settings):
    1. settings.brainPrimaryProvider (default: "anthropic")
    2. settings.brainFallbackOrder (parsed from comma/semicolon/pipe/newline list)
    3. Remaining DEFAULT_PROVIDER_CHAIN entries appended
    4. All deduped

  Can be OVERRIDDEN per-request via executionProfile.providerOrder.
  If executionProfile.disableFallback=true or only 1 provider, NO fallback.
  If executionProfile.internalOnly=true, ONLY codex lane runs.

FALLBACK DECISION (shouldFallbackToAlternateProvider):
  HARD STOPS (never fallback, throw instead):
    - "guardian blocked", "blocked by policy", "owner denied", "approval denied", "deny", "denied"
  TRIGGERS (do fallback):
    - 429, quota, credit, insufficient, rate limit, timed out, not configured,
      forbidden, unauthorized, authentication, model, unavailable, or any non-empty error

COST MODES:
  - "quality":  timeout 300s, maxTokens 1200, temp 0.2, full memory context
  - "balanced": timeout 90s,  maxTokens 850,  temp 0.2, last 10 lines of memory
  - "low":      timeout 70s,  maxTokens 600,  temp 0.1, last 6 lines of memory (DEFAULT)

SENSITIVE DATA BLOCKING:
  External providers (cursor, antigravity) are BLOCKED if:
    - Request contains images or files
    - Message or memory context contains passwords, tokens, API keys, private keys, etc.
  Internal providers (anthropic, codex, vertex, gemini, openclaw) are NOT blocked.

TEMPLATE FALLBACK:
  If ALL providers fail, returns a "low-cost fallback" text response listing
  which providers were tried and suggesting local tools instead.

PROVIDER ID NORMALIZATION:
  "gemini" / "geminiapi" → "gemini-api"
  "claude" / "anthropic-cli" → "anthropic"
  "gpt" / "chatgpt" → "openai"
  "vertex-ai" → "vertex"
  etc.

SUMMARY: THE ROUTING ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

There are TWO SEPARATE routing systems:

1. BRAIN ROUTER (brainOrchestrator.js)
   "Which LLM answers this prompt?"
   9 providers in a configurable fallback chain.
   Primary provider configurable at runtime. Fallback on error.
   External providers (openai/cursor/antigravity) blocked for sensitive data.
   Cost modes control timeout, token budget, and memory context size.

2. WORKER ROUTER (workerRouter.js)
   "Which agent executes this task?"
   4 worker lanes with different trust/capability profiles.
   Routes based on task type, sensitivity, size, and worker availability.
   Owner-plane work stays on highest-trust lane (codex or claude).

These are INDEPENDENT — a task can be routed to claude_max worker lane
while the brain orchestrator uses anthropic as primary brain provider.

NO ensemble/multi-model/cowork/parallel model patterns found in the codebase.
Each request goes to ONE provider at a time with sequential fallback.
