1. results.tsx — SORT COLUMN MISMATCH (LOW SEVERITY)
   Page allows sorting by 7 columns:
     completedAt, deviceSerialNumber, assayName, sampleId, resultState,
     operatorGroup, facilityId
   API allows sorting by 7 (different) columns:
     completedAt, resultState, deviceSerialNumber, assayCode, operatorId,
     readingValue, ingestedAt

   OVERLAP (3 columns work):  completedAt, deviceSerialNumber, resultState
   BROKEN (4 columns silently fall back to default sort):
     - assayName     (page sends it, API ignores it)
     - sampleId      (page sends it, API ignores it)
     - operatorGroup (page sends it, API ignores it)
     - facilityId    (page sends it, API ignores it)

   FIX OPTIONS:
   A) Add assayName, sampleId, operatorGroup, facilityId to the API's
      yup oneOf list and to ALLOWED_SORT_FIELDS in the repo.
   B) Remove sort click handlers from those 4 columns in the page.
   C) Map page column keys to API-accepted equivalents where possible
      (e.g., assayName -> assayCode).

NOTES:
- results/[id].tsx: Page declares numeric fields as `string` but the API
  returns number|null. The display() helper safely handles this via
  JavaScript type coercion. No crash, just a type annotation inaccuracy.
- devices.tsx: totalEvents is optional in the domain type but always
  returned by the aggregation pipeline in practice.
