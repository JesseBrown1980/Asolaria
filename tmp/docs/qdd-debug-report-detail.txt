2. API CALL CHAIN
=================
Frontend service (src/services/reports.ts line 157):

    export const getReport = async (id: string): Promise<ReportView> => {
      const report = await fetchJson(`/api/reports/${id}`, {
        method: 'GET',
        headers: { 'Content-Type': 'application/json' }
      });
      return report;
    };

fetchJson (src/utils/fetchJson.ts):
  - On 500/524: returns `false` silently (no error thrown)
  - On non-ok with errors array: throws ResponseError
  - On 401/403 (unauthorized): throws, alertService shows error, returns false
  - Result: if the API returns 500, `report` stays undefined, page stays on <Loading /> forever
  - Result: if the API returns 401/403, `report` stays undefined/false, page stays on <Loading /> forever


3. API ROUTE
============
File: D:\projects\QDD\ebacmap-master\apps\web-ebacmap\src\pages\api\reports\[id]\index.ts

GET endpoint uses:
  - Access control: `subjectModel: 'Report'`, domain: Report, action: View
  - Schema validation: `{ id: yup.string() }` — just validates `id` is a string
  - Use case: GetReportUseCase

ACCESS CONTROL FLOW (Endpoint.ts lines 295-331):
  1. If no user session → returns UnauthorizedError immediately
  2. If user.role is company_admin:
     - Calls `accessControlRepo.loadSubject('Report', subjectId)`
     - loadSubject does: `models.ReportModel.findById(subjectId)`
     - Returns `{ clientId: report.client, locationId: report.location[0] || report.location }`
     - Then checks: `user.clientId !== subject.clientId` → if mismatch → NotFoundError
     - Also checks: `subject.locationId && !user.locations.includes(subject.locationId)` → if mismatch → NotFoundError
  3. If user.role is restricted_user:
     - Needs location from request body/query/cookie
     - If no location → UnauthorizedError
     - Then does findTestResultClaim on the report domain (which doesn't filter reports, it filters test results)


4. USE CASE: GetReport
======================
File: D:\projects\QDD\ebacmap-master\apps\web-ebacmap\src\modules\reports\use-cases\GetReport\UseCase.ts

1. Validates id is a valid Mongo ObjectId via MongoIdentifier.build()
2. Calls models.ReportModel.findById(id).populate('notifications').lean()
3. If not found → Result.fail(NotFoundError)
4. Queries NotificationModel for matching notifications
5. Calls migrateReportToSections() to normalize legacy reports into section format
6. Maps to ReportView via toView()

CRITICAL: migrateReportToSections (libs/utils/src/lib/ReportMigrator.ts):
  - If reportType is 'single' or 'multi' → returns as-is
  - If reportType is 'ebacmap' with existing sections → returns as-is
  - Otherwise (legacy reports): creates a single section from report.filters
  - If report.filters is missing/undefined on a legacy report → will crash here


5. DTO MAPPING (toView)

Maps DB document to ReportView. Key fields:

mapSections filters out null sections, so empty sections won't crash here.

8. LIKELY FAILURE CAUSES
========================

A) AUTHENTICATION / AUTHORIZATION (MOST LIKELY):
   - The dev-bypass session user has clientId '69c41938d84980e337ac77cd'
   - The report's `client` field must match this clientId
   - The report's `location` field must be in user's locations array ['69c41938d84980e337ac77cf']
   - If the report belongs to a DIFFERENT client → loadSubject returns NotFoundError
   - NotFoundError returns 404, fetchJson parses the JSON error, throws ResponseError
   - SWR catches the error, retries... page stays on <Loading />

B) MISSING/NULL client FIELD ON DOCUMENT:
   - If the report document has no `client` field
   - loadSubject: report.client.toHexString() throws → caught, returns undefined
   - VerifyPermissions: !subject → NotFoundError
   - OR: GetReport use case: toView() → report.client.toHexString() throws

C) LEGACY REPORT WITH MISSING filters:
   - migrateReportToSections reads report.filters.chartType
   - If filters is null/undefined → TypeError: Cannot read property 'chartType' of null/undefined
   - This would be a 500 error, fetchJson returns false, page hangs

D) SECTIONS NULL AFTER LOAD:
   - Page line 268: `report.sections!.map(...)` — non-null assertion
   - If sections is undefined (legacy report where migration failed), this crashes client-side
   - Would show as a React error boundary or blank page, not infinite loading
