=== FINDING: DUAL-COLLECTION ARCHITECTURE ===

The eBacMap application uses a CQRS-like pattern with two collections:

  1. `testresults`      — write model (TestResultModel)
  2. `testresultreads`  — read model (TestResultReadModel) — DENORMALIZED

The seed script (scripts/seed-test-results.js) inserts 60 documents into
`testresults` with FLAT ObjectId references:

    client: ObjectId('69c41938d84980e337ac77cd')        // flat
    location: ObjectId('69c41938d84980e337ac77cf')       // flat
    site: ObjectId(...)                                  // flat

But the API (ListTests use case at line 1255 of TestResultRepo.ts) queries
the READ model using EMBEDDED object syntax:

    'client._id': new ObjectId(clientId)                 // nested
    'location._id': new ObjectId(location)               // nested

The read model schema (libs/db/src/models/TestResultRead.ts) expects:

    client:         { _id: ObjectId }                    // embedded
    location:       { _id: ObjectId, name: String }      // embedded
    site:           { _id: ObjectId, name: String, ... } // embedded
    zone:           { _id: ObjectId, name: String }      // embedded
    testDefinition: { _id: ObjectId, subTest: String, ...} // embedded
    category:       { _id: ObjectId, name: String }      // embedded

The denormalization happens in TestResultService.ts (line 219+) via
the `denormalizeTestResult()` method, which is called during the normal
create flow (CreateTestResult use case), NOT during bulk seed.

=== ROOT CAUSE ===

The seed script writes raw documents to the `testresults` (write model)
collection but does NOT create corresponding denormalized documents in
the `testresultreads` (read model) collection.

The API's list/search endpoint reads ONLY from `testresultreads`.

=== FIX REQUIRED ===

The seed script must ALSO insert denormalized documents into `testresultreads`.
Each document needs embedded objects instead of flat ObjectIds:

  Instead of:   client: ObjectId('69c41938d84980e337ac77cd')
  Must write:   client: { _id: ObjectId('69c41938d84980e337ac77cd') }

  Instead of:   location: ObjectId('69c41938d84980e337ac77cf')
  Must write:   location: { _id: ObjectId('69c41938d84980e337ac77cf'), name: 'Test Facility' }

  Instead of:   site: ObjectId(...)
  Must write:   site: { _id: ObjectId(...), name: '...', description: '...', siteId: '...' }

  (same pattern for zone, testDefinition, category, organism)

The denormalization shape is defined in:
  apps/web-ebacmap/src/modules/test-results/services/TestResultService.ts
  method: denormalizeTestResult() (line 203-280)
